Every company now ships software through the cloud, and the people who keep that delivery fast, repeatable and safe are DevOps engineers. This bootcamp takes you there from absolute scratch. You do not need any previous DevOps, cloud or Linux experience.

The bootcamp is not one tool. It is a chain of tools, and each one solves a problem the previous one leaves open. You start on a Linux server, learn to automate it with Bash, version your work with Git, build Java applications with Maven, rent servers on AWS, create those servers with Terraform, configure them with Ansible, package applications with Docker, run them at scale on Kubernetes, and finally connect everything with Jenkins pipelines.

<img src="/devops/devops-roadmap.svg" alt="DevOps Bootcamp roadmap from Linux to Jenkins CI/CD" width={960} height={520} />

By the end you will be able to:

- Work comfortably on a Linux server over SSH and automate routine work with Bash scripts
- Version code with Git and collaborate through GitHub branches and pull requests
- Build, test and package Java and Spring Boot applications with Maven
- Use the core AWS services: IAM, EC2, EBS, S3, RDS, VPC, load balancers and auto scaling
- Create cloud infrastructure from code with Terraform, and configure servers with Ansible playbooks
- Containerize applications with Docker and multi-stage Dockerfiles
- Deploy and operate applications on Kubernetes using Amazon EKS
- Build CI/CD pipelines in Jenkins that take code from Git all the way to a Kubernetes cluster

## Who this is for

Anyone who wants to start a career in DevOps or cloud: students, freshers, developers, testers, support engineers and system administrators. The bootcamp starts from zero, so the background you come from does not matter. What matters is that you practise. DevOps is not only about understanding a concept. It is about implementing it until it works, then breaking it and fixing it again.

## How the bootcamp is organised

Each tool has its own course in these docs. Follow them in this order, because later tools assume the earlier ones.

| Stage | Course | What it covers |
| --- | --- | --- |
| Foundation | [Computer & Programming Essentials](/docs/devops/computer-and-programming-essentials/programming-fundamentals) | How a CPU runs programs and how memory units work (optional) |
| Foundation | [Linux](/docs/linux/getting-started) | Lab setup on AWS, commands, files, permissions, users, networking, processes and Bash shell scripting |
| Code | [Git](/docs/git/getting-started) | Commits, branches, merging, rebasing, stash, forks and pull requests |
| Build | [Maven](/docs/maven/getting-started) | Build tools, the POM, dependencies, repositories, the build lifecycle and Spring Boot builds |
| Cloud | [AWS](/docs/aws/getting-started) | IAM, EC2, EBS, S3, RDS, VPC, Route 53, CloudWatch, Beanstalk, ECR and ECS |
| Infrastructure | [Terraform](/docs/terraform/getting-started) | Infrastructure as code, state, variables, outputs, taint and modules |
| Configuration | [Ansible](/docs/ansible/getting-started) | Inventory, ad hoc commands, playbooks, variables, vault, handlers and tags |
| Containers | [Docker](/docs/docker/getting-started) | Images, containers, Dockerfiles, multi-stage builds and networking |
| Orchestration | [Kubernetes](/docs/kubernetes/getting-started) | Pods, services, deployments, storage, autoscaling, Helm, Argo CD and monitoring on EKS |
| Automation | [Jenkins](/docs/jenkins/getting-started) | Jobs, agents, pipelines and an end-to-end CI/CD project with Docker and EKS |

## How to actually learn this

<Steps>
<Step>
### Build your own lab

Create a free tier AWS account early, launch a small Linux instance and do every exercise on a real server. Watching someone type commands is not the same as typing them yourself.
</Step>
<Step>
### Type every command

Small details decide whether DevOps commands work: a missing flag, a wrong port, a space in YAML. Typing them yourself trains your eye for those details.
</Step>
<Step>
### Break things on purpose

Stop a service, delete a pod, change a permission, push a bad commit. Then find out what happened and fix it. Debugging is the real daily work of a DevOps engineer.
</Step>
<Step>
### Clean up your cloud resources

EC2 instances, load balancers, NAT gateways and EKS clusters cost money while they run. Delete what you do not need at the end of each session, and set up a billing alert on day one.
</Step>
</Steps>

<Callout type="warn" title="Watch your AWS bill">
An EKS cluster and its worker nodes are not covered by the free tier. Create the cluster when you start a Kubernetes or Jenkins session and delete it when you finish. The [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html) page shows how to get an email before costs surprise you.
</Callout>

Start with the [Introduction](/docs/devops/introduction) to understand what DevOps actually is, then move through the courses in the order of the table above.
