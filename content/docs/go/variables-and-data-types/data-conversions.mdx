---
title: Data Conversions
description: How to convert between Go's types, which conversions need the strconv package, and which are not allowed at all.
---

Go never changes a value's type behind your back. If you have an `int` and need a `float64`, or a `string` that should become a number, you convert it yourself. Some conversions are a simple built-in cast; others go through the `strconv` package; and a few are simply not allowed, because the types have nothing in common.

## The Conversion Cheat Sheet

Here is the whole picture in one table. Keep it handy - most day-to-day conversion questions are answered here.

| From | To | How | Notes |
| ---- | -- | --- | ----- |
| `int` | `float64` | `float64(n)` | built-in cast |
| `int` | `string` | `strconv.Itoa(n)` | needs `strconv` |
| `int` | `bool` | not allowed | different purposes |
| `float64` | `int` | `int(f)` | truncates the decimals |
| `float64` | `string` | `strconv.FormatFloat(f, 'f', prec, bits)` | rounds to precision |
| `float64` | `bool` | not allowed | |
| `string` | `int` | `strconv.Atoi(s)` | returns value **and error** |
| `string` | `float64` | `strconv.ParseFloat(s, bits)` | returns value **and error** |
| `string` | `bool` | `strconv.ParseBool(s)` | returns value **and error** |
| `bool` | `string` | `strconv.FormatBool(b)` | |
| `bool` | `int` / `float` | not allowed | |

Two patterns stand out: number-to-number is a built-in cast, but anything involving a `string` goes through `strconv`.

## Casting Between Numbers

Converting between numeric types uses the target type as a function. Going from a whole number to a decimal is safe and lossless:

```go
count := 10
average := float64(count) / 3 // 3.3333333333333335
```

Going the other way, from `float64` to `int`, comes with a catch worth remembering.

<Callout type="warn">
`int(f)` **truncates** - it drops the decimal part instead of rounding. `int(6.9)` is `6`, not `7`. If you need rounding, round the float first (for example with `math.Round`) and then convert.
</Callout>

```go
price := 6.9
fmt.Println(int(price)) // 6, the .9 is thrown away
```

## Going Through strconv

Any conversion between text and another type lives in the `strconv` package. Import it and pick the function that matches the direction.

### Numbers to strings

```go
import "strconv"

s := strconv.Itoa(42)                       // int    → "42"
f := strconv.FormatFloat(3.14159, 'f', 2, 64) // float  → "3.14" (rounded to 2 places)
b := strconv.FormatBool(true)               // bool   → "true"
```

`FormatFloat` is the one with knobs: the `'f'` picks plain decimal notation, the precision says how many digits after the point (and it rounds), and the bit size matches your float type.

### Strings to other types

These are different, and the difference matters. A string might not contain a valid number, so each of these returns **two values**: the result and an error.

```go
n, err := strconv.Atoi("42")          // string → int
f, err := strconv.ParseFloat("3.14", 64) // string → float64
b, err := strconv.ParseBool("true")   // string → bool
```

You check the error before trusting the result:

```go
n, err := strconv.Atoi("hello")
if err != nil {
    fmt.Println("not a number:", err)
    return
}
fmt.Println(n * 2)
```

This is your first real taste of Go's error handling. Anything that parses text you did not create - user input, a file, a network response - can fail, and Go makes you acknowledge that with the error return.

## What You Cannot Convert

Some conversions make no sense, and Go refuses them at compile time:

- `int` to `bool`, and `bool` to `int` or `float` - a number and a truth value are different ideas, so there is no cast between them
- `float` to `bool`

If you genuinely need "is this number non-zero?", you write that logic yourself with a comparison like `n != 0`, rather than converting.
