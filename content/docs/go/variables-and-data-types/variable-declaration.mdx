---
title: Variable Declaration
description: Every way Go lets you declare a variable, grouped by when you would actually reach for each.
---

Go gives you not one way to declare a variable but eight. That sounds excessive until you realize each fits a slightly different moment: sometimes you want to be explicit, sometimes terse, sometimes you are declaring a value you will only fill in later. You will not use all eight daily, but recognizing them means no Go code can surprise you. Here they are, grouped by the situation they belong to.

## The var Family

`var` is the explicit workhorse. In its plainest form, you skip the type and let Go infer it from the value:

```go
var person = "Arshad" // Go infers string
```

State the type yourself when you want to be strict about it, or when the value alone would not make the type obvious:

```go
var person2 string = "Telusko"
```

`var` also declares several names at once. Let their types be inferred:

```go
var person4, person5 = "Akshay", "Naman"
```

Or pin them all to one shared type:

```go
var person6, person7 string = "Harsh", "Sushil"
```

## The := Shorthand

Inside a function, most Go you read uses the short form. No `var`, no type, just a name, `:=`, and a value:

```go
person3 := "नवीन"
```

It handles several variables too, and their types can even differ - a string and an int side by side:

```go
person8, age8 := "Shramik", 16
```

This is the idiomatic everyday choice. Reach for it first inside functions.

## Declaring Now, Filling In Later

Sometimes you want the name to exist before you have a value for it. Leave the value off and Go hands the variable a **zero value** suited to its type:

```go
var person9 string // starts as "" (empty string)
```

The same works for a group of one type, each starting at its zero value:

```go
var person10, age10 int // both start at 0
```

## The Eight at a Glance

| Form | Example |
| ---- | ------- |
| `var`, inferred | `var person = "Arshad"` |
| `var`, explicit type | `var person2 string = "Telusko"` |
| short `:=` | `person3 := "नवीन"` |
| multiple, inferred | `var person4, person5 = "Akshay", "Naman"` |
| multiple, typed | `var person6, person7 string = "Harsh", "Sushil"` |
| multiple, short | `person8, age8 := "Shramik", 16` |
| declared, no value | `var person9 string` |
| grouped, no value | `var person10, age10 int` |

## Two Rules That Come With Them

<Callout type="warn">
Declare a variable and never use it, and Go refuses to compile. It feels strict coming from other languages, but it is deliberate: it keeps dead code from accumulating. Use it or remove it.
</Callout>

The second rule is the quiet one behind the "no value" forms: a variable declared without a value is never garbage. Go gives it a defined default - `0` for numbers, `""` for strings, `false` for booleans. There is simply no such thing as an uninitialized variable in Go, an idea worth its own page next.

One boundary to keep in mind: `:=` only works **inside** functions. For a variable that lives at the package level, you must use one of the `var` forms.
