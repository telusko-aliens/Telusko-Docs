The same binary has to run on your laptop, in CI, in staging, and in production, with different databases, different log levels, and different credentials in each. How that difference is expressed decides how many incidents start with "it worked in staging".

## The twelve-factor position

Configuration lives in the environment, not in the code and not in a file committed to the repository.

```text
   Code            identical in every environment
   Configuration   differs per environment
   Secrets         configuration that must never be logged or committed
```

The test for whether something is configuration: could this repository be made public right now without leaking anything or breaking anything? If not, something is in the wrong place.

## The precedence order

```text
   defaults  <  config file  <  environment variables  <  command line flags
```

Defaults let the program run with no setup. A file suits complex structured settings. Environment variables are how containers and orchestrators supply configuration. Flags override everything for a single invocation.

```go title="internal/config/config.go"
package config

type Config struct {
    // Server
    Addr            string
    ReadTimeout     time.Duration
    WriteTimeout    time.Duration
    ShutdownTimeout time.Duration

    // Database
    DatabaseURL  string
    DBMaxConns   int
    DBMaxIdle    int

    // Observability
    LogLevel  slog.Level
    LogFormat string

    // Behaviour
    Environment    string
    AllowedOrigins []string
}

func Load(args []string) (Config, error) {
    cfg := Config{
        Addr:            ":8080",
        ReadTimeout:     15 * time.Second,
        WriteTimeout:    15 * time.Second,
        ShutdownTimeout: 30 * time.Second,
        DBMaxConns:      25,
        DBMaxIdle:       25,
        LogLevel:        slog.LevelInfo,
        LogFormat:       "json",
        Environment:     "development",
    }

    // Environment variables
    cfg.Addr = envStr("ADDR", cfg.Addr)
    cfg.DatabaseURL = os.Getenv("DATABASE_URL")
    cfg.Environment = envStr("ENVIRONMENT", cfg.Environment)
    cfg.DBMaxConns = envInt("DB_MAX_CONNS", cfg.DBMaxConns)
    cfg.ReadTimeout = envDur("READ_TIMEOUT", cfg.ReadTimeout)

    if v := os.Getenv("LOG_LEVEL"); v != "" {
        if err := cfg.LogLevel.UnmarshalText([]byte(v)); err != nil {
            return cfg, fmt.Errorf("LOG_LEVEL: %w", err)
        }
    }
    if v := os.Getenv("ALLOWED_ORIGINS"); v != "" {
        cfg.AllowedOrigins = strings.Split(v, ",")
    }

    // Flags, which win
    fs := flag.NewFlagSet("api", flag.ContinueOnError)
    fs.StringVar(&cfg.Addr, "addr", cfg.Addr, "listen address")
    fs.StringVar(&cfg.Environment, "env", cfg.Environment, "environment name")
    if err := fs.Parse(args); err != nil {
        return cfg, err
    }

    return cfg, cfg.Validate()
}
```

## Validate at startup, not at first use

```go
func (c Config) Validate() error {
    var errs []error

    if c.DatabaseURL == "" {
        errs = append(errs, errors.New("DATABASE_URL is required"))
    } else if u, err := url.Parse(c.DatabaseURL); err != nil {
        errs = append(errs, fmt.Errorf("DATABASE_URL is not a valid URL: %w", err))
    } else if u.Scheme != "postgres" && u.Scheme != "postgresql" {
        errs = append(errs, fmt.Errorf("DATABASE_URL scheme %q is not supported", u.Scheme))
    }

    if c.DBMaxConns < 1 {
        errs = append(errs, fmt.Errorf("DB_MAX_CONNS must be at least 1, got %d", c.DBMaxConns))
    }

    switch c.Environment {
    case "development", "staging", "production":
    default:
        errs = append(errs, fmt.Errorf("ENVIRONMENT %q must be development, staging or production", c.Environment))
    }

    if c.IsProduction() {
        if len(c.AllowedOrigins) == 0 {
            errs = append(errs, errors.New("ALLOWED_ORIGINS is required in production"))
        }
        if c.LogLevel == slog.LevelDebug {
            errs = append(errs, errors.New("debug logging is not permitted in production"))
        }
    }

    return errors.Join(errs...)
}

func (c Config) IsProduction() bool { return c.Environment == "production" }
```

<Callout type="info">
Collecting every error rather than returning on the first means an operator fixing a broken deployment sees all the problems at once. Returning early turns one bad deploy into four restarts, each revealing one more missing variable.
</Callout>

Fail loudly and immediately:

```go
func main() {
    cfg, err := config.Load(os.Args[1:])
    if err != nil {
        fmt.Fprintf(os.Stderr, "configuration error:\n%v\n", err)
        os.Exit(1)
    }
    // ...
}
```

A service that refuses to start with a clear message beats one that starts and fails on the first request that needs the missing value.

## Secrets

Everything above applies to secrets too, plus three rules that do not apply to ordinary configuration.

**Never commit them.** Not in code, not in a config file, not in a Dockerfile, not in a CI workflow, not in a comment. Git history is forever, so a secret committed once is a secret rotated.

```text title=".gitignore"
.env
*.pem
*.key
secrets/
```

Commit a documented example instead:

```bash title=".env.example"
# Copy to .env and fill in. Never commit .env.
DATABASE_URL=postgres://app:password@localhost:5432/appdb?sslmode=disable
JWT_SECRET=generate-with-openssl-rand-base64-32
STRIPE_API_KEY=sk_test_...
LOG_LEVEL=debug
```

**Never log them.**

```go
// This logs your database password
slog.Info("starting", "config", cfg)
slog.Debug("environment", "vars", os.Environ())
```

Make it structurally impossible with a type that cannot print itself:

```go
type Secret string

func (Secret) String() string                 { return "[REDACTED]" }
func (Secret) MarshalJSON() ([]byte, error)   { return []byte(`"[REDACTED]"`), nil }
func (Secret) LogValue() slog.Value           { return slog.StringValue("[REDACTED]") }

func (s Secret) Reveal() string { return string(s) }
```

```go
type Config struct {
    DatabaseURL Secret
    JWTSecret   Secret
    StripeKey   Secret
}

slog.Info("config loaded", "config", cfg)
// {"config":{"DatabaseURL":"[REDACTED]","JWTSecret":"[REDACTED]"}}

db, _ := sql.Open("pgx", cfg.DatabaseURL.Reveal())     // explicit at the one place it is needed
```

`LogValue` is the `slog` interface for controlling how a value appears in logs. Implementing all three methods covers printing, JSON, and structured logging.

**Rotate them.** Any secret that has ever been in a log, a screenshot, a chat message, or a git history is compromised. Design for rotation from the start.

## Where secrets come from

```text
   Local development     .env file, gitignored
   CI                    the platform's secret store
   Kubernetes            Secrets, ideally from an external operator
   AWS                   Secrets Manager or Parameter Store
   Anywhere              HashiCorp Vault
```

Loading a `.env` file in development only:

```go
import "github.com/joho/godotenv"

func Load(args []string) (Config, error) {
    // Ignore the error: the file is expected to be absent in production.
    _ = godotenv.Load()

    // ... read from the environment as normal
}
```

Reading a secret from a mounted file, which is how Kubernetes and Docker secrets work:

```go
func secretFromFile(path, envKey string) (Secret, error) {
    // A _FILE variable pointing at a mounted secret takes precedence.
    if p := os.Getenv(envKey + "_FILE"); p != "" {
        data, err := os.ReadFile(p)
        if err != nil {
            return "", fmt.Errorf("reading %s: %w", p, err)
        }
        return Secret(strings.TrimSpace(string(data))), nil
    }
    return Secret(os.Getenv(envKey)), nil
}
```

<Callout type="warn">
Environment variables are visible to anything that can read `/proc/<pid>/environ`, they appear in crash dumps, and orchestrators often display them in a dashboard. Files mounted with restrictive permissions are meaningfully safer for high-value secrets, which is why Docker and Kubernetes both offer the `_FILE` convention.
</Callout>

## Configuration files, when you need them

Environment variables are flat strings. For genuinely structured settings, a file is better:

```yaml title="config.yaml"
server:
  addr: ":8080"
  timeouts:
    read: 15s
    write: 15s

database:
  max_conns: 25
  max_idle: 25

features:
  new_checkout: false
  rate_limiting: true

rate_limits:
  - path: /api/v1/search
    rps: 10
  - path: /api/v1/upload
    rps: 2
```

```go
type FileConfig struct {
    Server struct {
        Addr     string `yaml:"addr"`
        Timeouts struct {
            Read  time.Duration `yaml:"read"`
            Write time.Duration `yaml:"write"`
        } `yaml:"timeouts"`
    } `yaml:"server"`

    Features map[string]bool `yaml:"features"`
}

func loadFile(path string) (FileConfig, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return FileConfig{}, fmt.Errorf("reading %s: %w", path, err)
    }

    var fc FileConfig
    if err := yaml.Unmarshal(data, &fc); err != nil {
        return FileConfig{}, fmt.Errorf("parsing %s: %w", path, err)
    }
    return fc, nil
}
```

Keep secrets out of the file. The file goes in the repository, the secrets come from the environment.

## Feature flags

```go
type Features struct {
    mu    sync.RWMutex
    flags map[string]bool
}

func (f *Features) Enabled(name string) bool {
    f.mu.RLock()
    defer f.mu.RUnlock()
    return f.flags[name]
}

func (f *Features) Set(name string, on bool) {
    f.mu.Lock()
    defer f.mu.Unlock()
    f.flags[name] = on
}
```

```go
if features.Enabled("new_checkout") {
    return s.newCheckout(ctx, order)
}
return s.legacyCheckout(ctx, order)
```

A missing flag reads as false, so an unknown name safely disables the feature. That is the zero value behaviour from the variables section doing useful work.

Flags accumulate. Delete each one once the feature is fully rolled out, or you end up with a codebase where every path has two versions and nobody knows which is live.

## Configuration in tests

Because `Load` takes its arguments as a parameter, a test can supply them:

```go
func TestConfigValidation(t *testing.T) {
    tests := []struct {
        name    string
        env     map[string]string
        wantErr string
    }{
        {
            name:    "missing database url",
            env:     map[string]string{},
            wantErr: "DATABASE_URL is required",
        },
        {
            name: "production without origins",
            env: map[string]string{
                "DATABASE_URL": "postgres://localhost/db",
                "ENVIRONMENT":  "production",
            },
            wantErr: "ALLOWED_ORIGINS is required",
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            for k, v := range tt.env {
                t.Setenv(k, v)         // restored automatically
            }

            _, err := Load(nil)

            if err == nil || !strings.Contains(err.Error(), tt.wantErr) {
                t.Errorf("err = %v, want it to contain %q", err, tt.wantErr)
            }
        })
    }
}
```

`t.Setenv` sets a variable for the duration of the test and restores it afterwards, which is exactly what you want and is easy to get wrong by hand.

## The rules

1. **Configuration comes from the environment.** Code is identical everywhere.
2. **Validate everything at startup.** Report every problem at once.
3. **Provide sensible defaults.** The program should run with minimal setup.
4. **Secrets never enter the repository.** Commit a documented example instead.
5. **Wrap secrets in a type that cannot print itself.**
6. **Layer the sources:** defaults, then file, then environment, then flags.
7. **Test the configuration loader.** It is the code that runs before anything else.
