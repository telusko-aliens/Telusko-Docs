Every programmer remembers their first "Hello World." It is tiny on purpose. Its real job is not to impress anyone but to prove two things at once: that your setup works, and that you understand the skeleton every Go program is built on. Write this one carefully and the next hundred programs will feel familiar.

## Write It and Run It

Make a file ending in `.go` - `main.go` is the usual choice - and type this in:

```go
package main

import "fmt"

func main() {
    fmt.Println("Hello World")
    fmt.Println("My name is Akshay")
}
```

Then, from the terminal in that folder:

```bash
go run main.go
```

```text
Hello World
My name is Akshay
```

That is a complete Go program. Now let us take it apart, because those few lines contain four ideas you will use forever.

## Reading It Line by Line

**`package main`** comes first in every Go file, declaring which package the file belongs to. The name `main` is special: it tells Go this file is part of a runnable program rather than a library.

**`import "fmt"`** pulls in the `fmt` package - short for "format" - which holds the functions for printing to and reading from the console. You import what you need and use it; here that is `fmt.Println`.

**`func main()`** is the **entry point**. When the program starts, Go looks for exactly this function and begins running from its first line.

**`fmt.Println(...)`** is a single statement that prints a line of text. Two of them run in order, top to bottom, which is why the output has two lines.

```text
   go run main.go
        │
        ▼
   compile  ──►  start at func main()  ──►  run each line in order
```

## Print or Println?

The `fmt` package gives you a choice about newlines:

| Function | What it does |
| -------- | ------------ |
| `fmt.Print` | prints the text with no line break after it |
| `fmt.Println` | prints the text and adds a newline |

The `ln` literally stands for "line." It tacks a newline onto the end so your next print starts fresh, which is why the two greetings above land on separate lines instead of mashing together.

## The Two Things the Compiler Insists On

<Callout type="warn">
The Go compiler specifically looks for `package main` and a function called `main`. Rename or drop either one and the program will not run.
</Callout>

Those two - `package main` and `func main` - are non-negotiable. They are what mark your code as a runnable program and tell Go where to begin. The **file name**, on the other hand, is entirely yours. You could call it `first.go` instead of `main.go` and nothing changes, as long as the package and function inside are still named `main`. The compiler cares about what is written in the file, not what the file is called.

With the skeleton clear, you are ready to start filling it with actual logic.
