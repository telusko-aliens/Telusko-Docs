title: CRUD Queries

Create, read, update, delete. Four operations that make up most of what a service does with a database, and each one has a Go-specific detail that is worth getting right the first time.

The schema for this page:

```sql
CREATE TABLE tasks (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title       TEXT NOT NULL,
    notes       TEXT NOT NULL DEFAULT '',
    status      TEXT NOT NULL DEFAULT 'todo',
    due_at      TIMESTAMPTZ,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_tasks_user_status ON tasks (user_id, status);
CREATE INDEX idx_tasks_due ON tasks (due_at) WHERE due_at IS NOT NULL;
```

## Create, with RETURNING

```go
func (s *Store) CreateTask(ctx context.Context, t *Task) error {
    const query = `
        INSERT INTO tasks (user_id, title, notes, status, due_at)
        VALUES ($1, $2, $3, $4, $5)
        RETURNING id, created_at, updated_at`

    err := s.db.QueryRowContext(ctx, query,
        t.UserID, t.Title, t.Notes, t.Status, t.DueAt,
    ).Scan(&t.ID, &t.CreatedAt, &t.UpdatedAt)

    if err != nil {
        var pgErr *pgconn.PgError
        if errors.As(err, &pgErr) {
            switch pgErr.Code {
            case "23505":
                return ErrDuplicate
            case "23503":
                return ErrInvalidUser
            }
        }
        return fmt.Errorf("creating task: %w", err)
    }

    return nil
}
```

`RETURNING` is PostgreSQL's answer to "what ID did that get". One round trip instead of an insert followed by a select, and the database-generated defaults come back with it.

The insert uses `QueryRowContext` rather than `ExecContext`, because `RETURNING` produces a row.

Translating the constraint violation codes here matters. Above this layer, nobody should have to know that 23505 means a unique index was violated.

### Bulk insert

```go
func (s *Store) CreateTasks(ctx context.Context, tasks []*Task) error {
    if len(tasks) == 0 {
        return nil
    }

    var (
        placeholders = make([]string, 0, len(tasks))
        args         = make([]any, 0, len(tasks)*4)
    )

    for i, t := range tasks {
        n := i * 4
        placeholders = append(placeholders,
            fmt.Sprintf("($%d, $%d, $%d, $%d)", n+1, n+2, n+3, n+4))
        args = append(args, t.UserID, t.Title, t.Notes, t.Status)
    }

    query := `INSERT INTO tasks (user_id, title, notes, status) VALUES ` +
        strings.Join(placeholders, ", ")

    if _, err := s.db.ExecContext(ctx, query, args...); err != nil {
        return fmt.Errorf("bulk inserting tasks: %w", err)
    }
    return nil
}
```

One statement for a hundred rows instead of a hundred round trips. For thousands of rows, `COPY` is faster still.

PostgreSQL has a limit of 65535 parameters per statement, so batch in chunks when the count could be large.

## Read

### One row

```go
func (s *Store) GetTask(ctx context.Context, id string) (*Task, error) {
    const query = `
        SELECT id, user_id, title, notes, status, due_at, created_at, updated_at
        FROM tasks
        WHERE id = $1`

    var t Task
    err := s.db.QueryRowContext(ctx, query, id).Scan(
        &t.ID, &t.UserID, &t.Title, &t.Notes,
        &t.Status, &t.DueAt, &t.CreatedAt, &t.UpdatedAt,
    )

    if errors.Is(err, sql.ErrNoRows) {
        return nil, ErrNotFound
    }
    if err != nil {
        return nil, fmt.Errorf("getting task %s: %w", id, err)
    }

    return &t, nil
}
```

<Callout type="warn">
Never write `SELECT *`. When someone adds a column, every `Scan` in the codebase breaks with a "expected N destination arguments" error, and worse, a reordered column silently scans the wrong data into the wrong field. Listing columns explicitly costs one line and prevents both.
</Callout>

### Many rows

```go
func (s *Store) ListTasks(ctx context.Context, userID string, limit, offset int) ([]*Task, error) {
    const query = `
        SELECT id, user_id, title, notes, status, due_at, created_at, updated_at
        FROM tasks
        WHERE user_id = $1
        ORDER BY created_at DESC
        LIMIT $2 OFFSET $3`

    rows, err := s.db.QueryContext(ctx, query, userID, limit, offset)
    if err != nil {
        return nil, fmt.Errorf("listing tasks: %w", err)
    }
    defer rows.Close()

    tasks := make([]*Task, 0, limit)
    for rows.Next() {
        var t Task
        if err := rows.Scan(
            &t.ID, &t.UserID, &t.Title, &t.Notes,
            &t.Status, &t.DueAt, &t.CreatedAt, &t.UpdatedAt,
        ); err != nil {
            return nil, fmt.Errorf("scanning task: %w", err)
        }
        tasks = append(tasks, &t)
    }

    if err := rows.Err(); err != nil {
        return nil, fmt.Errorf("iterating tasks: %w", err)
    }

    return tasks, nil
}
```

The `rows.Err()` check is the line people leave out. Without it, a connection failure partway through iteration is indistinguishable from reaching the end.

Since the scan block repeats in every list function, extract it:

```go
func scanTask(s interface{ Scan(...any) error }) (*Task, error) {
    var t Task
    err := s.Scan(&t.ID, &t.UserID, &t.Title, &t.Notes,
        &t.Status, &t.DueAt, &t.CreatedAt, &t.UpdatedAt)
    if err != nil {
        return nil, err
    }
    return &t, nil
}
```

That interface accepts both `*sql.Row` and `*sql.Rows`, so one function serves both the single and the multiple cases.

### Dynamic filters

Query building is where SQL injection creeps back in. The safe pattern keeps the conditions and the arguments in step:

```go
type TaskFilter struct {
    UserID   string
    Status   string
    DueAfter *time.Time
    Search   string
}

func (s *Store) FindTasks(ctx context.Context, f TaskFilter, limit, offset int) ([]*Task, error) {
    var (
        conditions = []string{"user_id = $1"}
        args       = []any{f.UserID}
    )

    if f.Status != "" {
        args = append(args, f.Status)
        conditions = append(conditions, fmt.Sprintf("status = $%d", len(args)))
    }
    if f.DueAfter != nil {
        args = append(args, *f.DueAfter)
        conditions = append(conditions, fmt.Sprintf("due_at > $%d", len(args)))
    }
    if f.Search != "" {
        args = append(args, "%"+f.Search+"%")
        conditions = append(conditions, fmt.Sprintf("title ILIKE $%d", len(args)))
    }

    args = append(args, limit, offset)

    query := fmt.Sprintf(`
        SELECT id, user_id, title, notes, status, due_at, created_at, updated_at
        FROM tasks
        WHERE %s
        ORDER BY created_at DESC
        LIMIT $%d OFFSET $%d`,
        strings.Join(conditions, " AND "), len(args)-1, len(args))

    rows, err := s.db.QueryContext(ctx, query, args...)
    // ... same iteration as above
}
```

Every user value goes into `args`. Only the placeholder numbers and the fixed condition text are formatted into the string, and those come from your own code.

## Update

```go
func (s *Store) UpdateTask(ctx context.Context, t *Task) error {
    const query = `
        UPDATE tasks
        SET title = $1, notes = $2, status = $3, due_at = $4, updated_at = now()
        WHERE id = $5
        RETURNING updated_at`

    err := s.db.QueryRowContext(ctx, query,
        t.Title, t.Notes, t.Status, t.DueAt, t.ID,
    ).Scan(&t.UpdatedAt)

    if errors.Is(err, sql.ErrNoRows) {
        return ErrNotFound
    }
    if err != nil {
        return fmt.Errorf("updating task %s: %w", t.ID, err)
    }
    return nil
}
```

`RETURNING` doing double duty again: it gives you the new timestamp and it turns "no such row" into `sql.ErrNoRows`, which saves a separate `RowsAffected` check.

### Partial update

```go
func (s *Store) PatchTask(ctx context.Context, id string, p TaskPatch) error {
    var (
        sets = []string{"updated_at = now()"}
        args []any
    )

    if p.Title != nil {
        args = append(args, *p.Title)
        sets = append(sets, fmt.Sprintf("title = $%d", len(args)))
    }
    if p.Status != nil {
        args = append(args, *p.Status)
        sets = append(sets, fmt.Sprintf("status = $%d", len(args)))
    }
    if p.DueAt != nil {
        args = append(args, *p.DueAt)
        sets = append(sets, fmt.Sprintf("due_at = $%d", len(args)))
    }

    if len(args) == 0 {
        return nil          // nothing to change
    }

    args = append(args, id)
    query := fmt.Sprintf(`UPDATE tasks SET %s WHERE id = $%d`,
        strings.Join(sets, ", "), len(args))

    result, err := s.db.ExecContext(ctx, query, args...)
    if err != nil {
        return fmt.Errorf("patching task %s: %w", id, err)
    }

    n, _ := result.RowsAffected()
    if n == 0 {
        return ErrNotFound
    }
    return nil
}
```

### Optimistic locking

When two users edit the same record, the last write silently wins. A version column prevents that:

```go
func (s *Store) UpdateTaskVersioned(ctx context.Context, t *Task) error {
    const query = `
        UPDATE tasks
        SET title = $1, status = $2, version = version + 1, updated_at = now()
        WHERE id = $3 AND version = $4
        RETURNING version, updated_at`

    err := s.db.QueryRowContext(ctx, query,
        t.Title, t.Status, t.ID, t.Version,
    ).Scan(&t.Version, &t.UpdatedAt)

    if errors.Is(err, sql.ErrNoRows) {
        // Either the row is gone or somebody else updated it first.
        return ErrConflict
    }
    if err != nil {
        return fmt.Errorf("updating task: %w", err)
    }
    return nil
}
```

The caller gets a 409 and can re-read and retry, rather than silently overwriting somebody's work.

## Delete

```go
func (s *Store) DeleteTask(ctx context.Context, id string) error {
    result, err := s.db.ExecContext(ctx, `DELETE FROM tasks WHERE id = $1`, id)
    if err != nil {
        return fmt.Errorf("deleting task %s: %w", id, err)
    }

    n, err := result.RowsAffected()
    if err != nil {
        return fmt.Errorf("checking rows affected: %w", err)
    }
    if n == 0 {
        return ErrNotFound
    }
    return nil
}
```

### Soft delete

```sql
ALTER TABLE tasks ADD COLUMN deleted_at TIMESTAMPTZ;
CREATE INDEX idx_tasks_active ON tasks (user_id) WHERE deleted_at IS NULL;
```

```go
func (s *Store) SoftDeleteTask(ctx context.Context, id string) error {
    result, err := s.db.ExecContext(ctx,
        `UPDATE tasks SET deleted_at = now() WHERE id = $1 AND deleted_at IS NULL`,
        id)
    // ...
}
```

<Callout type="warn">
Soft deletes are easy to add and easy to get wrong. Every single query from that point on must include `AND deleted_at IS NULL`, and the one you forget will show deleted records to users. Consider whether you actually need it, and if you do, funnel every read through helpers that add the condition rather than writing it by hand each time.
</Callout>

## Counting and pagination

```go
func (s *Store) CountTasks(ctx context.Context, userID string) (int, error) {
    var n int
    err := s.db.QueryRowContext(ctx,
        `SELECT count(*) FROM tasks WHERE user_id = $1`, userID).Scan(&n)
    if err != nil {
        return 0, fmt.Errorf("counting tasks: %w", err)
    }
    return n, nil
}
```

`LIMIT` and `OFFSET` are simple and get slow. `OFFSET 100000` makes the database read and discard a hundred thousand rows.

Cursor pagination stays fast at any depth:

```go
func (s *Store) ListTasksAfter(ctx context.Context, userID string,
    after time.Time, limit int) ([]*Task, error) {

    const query = `
        SELECT id, user_id, title, notes, status, due_at, created_at, updated_at
        FROM tasks
        WHERE user_id = $1 AND created_at < $2
        ORDER BY created_at DESC
        LIMIT $3`

    rows, err := s.db.QueryContext(ctx, query, userID, after, limit)
    // ...
}
```

The client sends back the last `created_at` it saw. The index does the work, and page one thousand is as fast as page one.

## Related data, without N+1

```go
// Bad: one query, then one per task
tasks, _ := store.ListTasks(ctx, userID, 100, 0)
for _, t := range tasks {
    t.User, _ = store.GetUser(ctx, t.UserID)     // 100 more queries
}
```

Either join:

```go
const query = `
    SELECT t.id, t.title, t.status, u.id, u.name, u.email
    FROM tasks t
    JOIN users u ON u.id = t.user_id
    WHERE t.user_id = $1`

for rows.Next() {
    var t Task
    var u User
    rows.Scan(&t.ID, &t.Title, &t.Status, &u.ID, &u.Name, &u.Email)
    t.User = &u
    tasks = append(tasks, &t)
}
```

Or fetch in two queries and stitch:

```go
tasks, _ := store.ListTasks(ctx, userID, 100, 0)

ids := make([]string, 0, len(tasks))
for _, t := range tasks {
    ids = append(ids, t.UserID)
}

users, _ := store.GetUsersByIDs(ctx, ids)     // WHERE id = ANY($1)

byID := make(map[string]*User, len(users))
for _, u := range users {
    byID[u.ID] = u
}
for _, t := range tasks {
    t.User = byID[t.UserID]
}
```

Two queries instead of a hundred and one. `WHERE id = ANY($1)` with a `[]string` argument is the PostgreSQL idiom, and `pgx` passes the slice directly.
