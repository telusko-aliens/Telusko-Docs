Welcome to the **LangChain4j Docs**.

Most Java developers meet AI the same way. There is an application that already works, and now it needs one more feature: a chatbot, a summary, a search that understands meaning. The model lives behind an API, and somebody has to write the code that talks to it.

LangChain4j is a Java library that makes this code short. These docs do not start with it, though. They follow the LangChain4j course by Navin Reddy at Telusko, and the course makes one deliberate choice: first call the model with the plain OpenAI Java SDK, feel what is repetitive and what is locked to one vendor, and only then bring in the library that removes those problems.

Every page here follows one lecture of that course, with the code, the output and the mistakes made along the way.

## What we build

One small Maven project named `lc4j`, with a single class, `App.java`. Each lecture changes that class a little. There is no web framework and no database, so nothing hides the code that talks to the model.

## What you need

You should be comfortable with:

- Core Java: classes, interfaces, records, lists and lambdas
- Running a Maven project in an IDE

To run the code yourself:

| Requirement | Used for | Notes |
| --- | --- | --- |
| JDK 25 | Everything | The project's `pom.xml` sets `maven.compiler.release` to 25. The libraries themselves work on older versions too |
| Maven | Building the project | Comes with most IDEs |
| VS Code with the Extension Pack for Java, or any Java IDE | Writing and running the code | The course uses VS Code. IntelliJ IDEA works the same way |
| An OpenAI API key | The OpenAI option in every lesson | API usage is paid. The course says a few dollars of credit is enough for all lessons |
| [Ollama](https://ollama.com) | The local option in every lesson | Free. Needs a machine that can run a small model |

You do **not** need both OpenAI and Ollama. Almost every lesson shows the same code for both, and you can follow the whole course with only one of them.

<Callout type="info" title="Which option should you pick?">
OpenAI gives faster and more reliable answers and costs a little money. Ollama costs nothing and keeps everything on your machine, but small local models are slower and make more mistakes. If you can, set up both. Seeing the same Java code work against two very different servers is one of the main lessons of this course.
</Callout>

<Callout type="warn" title="Keep your API key out of Git">
The OpenAI key goes into a `.env` file, and `.env` goes into `.gitignore` before the first commit. A key that reaches a public repository, a screenshot or a screen recording must be treated as stolen: delete it in the OpenAI dashboard and create a new one.
</Callout>

## The libraries

Four dependencies do all the work. Their names are easy to mix up, so here is who does what:

| Dependency | Version in the course | Role |
| --- | --- | --- |
| `com.openai:openai-java` | 4.91.0 | The official OpenAI SDK. Used alone in steps 4 to 7 |
| `dev.langchain4j:langchain4j` | 1.22.0 | The main LangChain4j module: AI Services, chat memory, tools, document splitters, the in-memory embedding store |
| `dev.langchain4j:langchain4j-open-ai` | 1.22.0 | Connects LangChain4j to OpenAI chat and embedding models |
| `dev.langchain4j:langchain4j-ollama` | 1.22.0 | Connects LangChain4j to models served by Ollama |

All 14 lecture projects were compiled for these docs against exactly these versions. Newer versions exist. Use the ones above while you learn, so that your code matches the pages, and move to the latest release when you start your own project.

## How to learn from these docs

<Steps>
<Step>
### Type the code

Create the project and write `App.java` yourself. The repository is there to compare against when something does not work.
</Step>
<Step>
### Run every version

Most lessons change one thing and run again. Do the same. The difference between two runs is where the understanding comes from.
</Step>
<Step>
### Make the mistakes too

The course runs into real errors: a missing API key, a wrong import, a tool that is not a tool, a model that refuses a request. Each page shows the error message, the cause and the fix.
</Step>
<Step>
### Expect different words

A model does not give the same answer twice. Your output will have the same meaning as the output on these pages, with different wording.
</Step>
<Step>
### Check the official docs for what is current

Models, prices and library versions change quickly. Where something differs from the course, the page says so in a note. The official documentation linked at the end of each page is the source of truth.
</Step>
</Steps>

## What you will be able to do

By the end, you will be able to:

- Explain what a token, a system message, a reasoning effort and a structured output are
- Call OpenAI and Ollama models from plain Java with the OpenAI SDK
- Use `ChatModel` so that your code does not depend on one provider
- Build AI Services with `@SystemMessage`, records as return types and chat memory
- Give a model tools with `@Tool` and explain every step of a tool call
- Create embeddings, compare them and search them in an embedding store
- Build a RAG pipeline that answers from your own documents
