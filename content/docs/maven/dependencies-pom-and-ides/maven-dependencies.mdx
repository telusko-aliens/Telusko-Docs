Almost no real application is written from scratch. You use frameworks and libraries written by other teams: Spring for application structure, Hibernate for databases, JUnit for testing, a Kafka or Redis client for messaging. Each of these is someone else's code, packaged as one or more JAR files full of classes, interfaces and annotations you want to use.

Without Maven you would search the internet, download those JARs and add them to your build path by hand (we saw that pain in [Why and what is build tool](/docs/maven/build-tool-fundamentals/why-and-what-is-build-tool)). With Maven you write a few lines in `pom.xml` and Maven does the rest. Those libraries are called **dependencies**: things your project depends on to compile or run.

## Step 1: find the dependency

Search for the library on a Maven repository search site. Two common ones:

| Site | What it is |
| --- | --- |
| [central.sonatype.com](https://central.sonatype.com/) | The official search for Maven Central, run by Sonatype, the steward of Central |
| [mvnrepository.com](https://mvnrepository.com/) | A popular third party index of Central and other repositories. The video uses this one |

In the demo we search for **spring-core**, open it, pick version **6.2.8**, and copy the Maven snippet:

```xml
<!-- https://mvnrepository.com/artifact/org.springframework/spring-core -->
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>6.2.8</version>
</dependency>
```

A dependency is identified by the same GAV coordinates you learned in [Maven Terminologies](/docs/maven/maven-projects-and-goals/maven-terminologies): `org.springframework:spring-core:6.2.8`.

<Callout type="info" title="Picking a version">
Prefer the newest stable release of the line your project uses. Skip versions with `-M1`, `-RC1` or `-SNAPSHOT`, which are milestones, release candidates and development builds. Both search sites also show known vulnerabilities for each version, which is worth a glance before you choose.
</Callout>

## Step 2: add it to pom.xml

Open `telusko-app/pom.xml` in any editor or IDE. Find the `<dependencies>` section, which already contains JUnit, and paste the new `<dependency>` **inside** it, next to the existing one:

```xml title="pom.xml"
<dependencies>
  <dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>3.8.1</version>
    <scope>test</scope>
  </dependency>

  <!-- https://mvnrepository.com/artifact/org.springframework/spring-core -->
  <dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>6.2.8</version>
  </dependency>
</dependencies>
```

![pom.xml open in IntelliJ IDEA with the junit dependency and the new spring-core 6.2.8 dependency inside the dependencies element](https://dyz1pdcuffwr5.cloudfront.net/Maven/screenshots/spring-core-dependency-pom.webp)

*The spring-core dependency pasted inside `<dependencies>`, right after JUnit. (This is the archetype 1.0 POM. If you used archetype 1.5, your JUnit entries look different, and that is fine.)*

The meaning of these lines is simply: "Maven, this project depends on spring-core 6.2.8, please get it for me." Save the file.

<Callout type="warn" title="Spring 6 needs Java 17">
Spring Framework 6 is compiled for Java 17. If your POM still compiles for Java 8, or your JDK is older than 17, the build fails as soon as your code uses Spring classes. Make sure your project targets Java 17 or newer, as set up in [Maven Goals](/docs/maven/maven-projects-and-goals/maven-goals).
</Callout>

## Step 3: build and watch the download

From the project folder:

```bash
mvn clean
mvn package
```

(or `mvn clean package` in one go). Near the top of the output you now see lines like:

```text
Downloading from central: https://repo.maven.apache.org/maven2/org/springframework/spring-core/6.2.8/spring-core-6.2.8.pom
Downloaded from central: https://repo.maven.apache.org/maven2/org/springframework/spring-core/6.2.8/spring-core-6.2.8.jar (2.0 MB at ...)
...
[INFO] BUILD SUCCESS
```

Maven fetched the JAR from Maven Central and put it on the project's classpath. If you open the project in an IDE, you can now `import org.springframework...` classes and they compile. You did not download or copy anything yourself.

You can add as many dependencies as you need: Spring, Spring Security, Hibernate, JUnit, Kafka, Redis clients. Each one is another `<dependency>` block inside the same `<dependencies>` element.

## Transitive dependencies: the ones you did not ask for

Libraries have their own dependencies. `spring-core` 6.2.x needs `spring-jcl` (Spring's logging bridge). You never declared it, but Maven reads spring-core's own POM, sees that requirement, and downloads it too. These are **transitive dependencies**.

![telusko-app depends directly on spring-core and junit; spring-core brings spring-jcl as a transitive dependency](https://dyz1pdcuffwr5.cloudfront.net/Maven/transitive-dependencies.svg)

See the full tree at any time:

```bash
mvn dependency:tree
```

```text
[INFO] com.telusko:telusko-app:jar:1.0-SNAPSHOT
[INFO] +- junit:junit:jar:3.8.1:test
[INFO] \- org.springframework:spring-core:jar:6.2.8:compile
[INFO]    \- org.springframework:spring-jcl:jar:6.2.8:compile
```

This command is your best friend when two libraries pull in different versions of the same JAR. When that happens Maven picks the version **nearest** to your project in the tree. If you need a specific version, declare it directly in your own POM, and that declaration wins.

## Dependency scopes

The `<scope>` element controls where a dependency is available. If you leave it out, the scope is `compile`.

| Scope | Available when | Packaged in WAR / fat JAR? | Typical example |
| --- | --- | --- | --- |
| `compile` (default) | Compiling, testing, running | Yes | Spring, Jackson |
| `test` | Only compiling and running tests | No | JUnit, Mockito |
| `provided` | Compiling and testing. The runtime environment supplies it | No | Servlet API (Tomcat already has it) |
| `runtime` | Testing and running, not compiling | Yes | JDBC drivers such as MySQL Connector/J |
| `system` | Like `provided`, but from a file path on your disk | No | Avoid. Legacy only |
| `import` | Only for importing a BOM in `<dependencyManagement>` | Not applicable | Spring Boot or JUnit BOMs |

That is why JUnit has `<scope>test</scope>`: you need it to run tests, but it must never ship inside your production JAR.

## Common problems

<Accordions>
<Accordion title="Could not find artifact ... in central">
A typo in the groupId, artifactId or version, or a version that does not exist. Copy the coordinates again from the search site. Also check you did not paste the dependency outside `<dependencies>`.
</Accordion>
<Accordion title="package org.springframework... does not exist">
The dependency is not in the POM, the POM was not saved, or your IDE has not reloaded the project. Save, then reload Maven in the IDE (IntelliJ: the Maven tool window's reload button; Eclipse: right click the project, then **Maven > Update Project**).
</Accordion>
<Accordion title="Builds work at home but fail in the office">
The office network may block `repo.maven.apache.org` or require a proxy. Companies usually provide an internal repository mirror. See [Maven Repositories](/docs/maven/dependencies-pom-and-ides/maven-repositories).
</Accordion>
</Accordions>

## Try It Yourself

1. Add `spring-core` 6.2.8 to `telusko-app`, run `mvn clean package`, and find the `Downloading from central` lines for it.
2. Run `mvn dependency:tree` and identify the transitive dependency spring-core brought in.
3. Add `com.mysql:mysql-connector-j` with `<scope>runtime</scope>` and run `mvn dependency:tree` again. Note the scope shown at the end of the line.
4. Introduce a typo in the version (for example `6.2.88`), build, and read the error. Fix it.
