## Command cheat sheet

```bash title="Create projects"
# Standalone Java project (JAR)
mvn archetype:generate -DgroupId=com.telusko -DartifactId=telusko-app -DarchetypeArtifactId=maven-archetype-quickstart -DarchetypeVersion=1.5 -DinteractiveMode=false

# Web project (WAR)
mvn archetype:generate -DgroupId=com.telusko -DartifactId=telusko-web-app -DarchetypeArtifactId=maven-archetype-webapp -DarchetypeVersion=1.5 -DinteractiveMode=false
```

| Command | What it does |
| --- | --- |
| `mvn -v` | Show Maven version, Maven home and the Java it uses |
| `mvn clean` | Delete `target/` |
| `mvn compile` | Compile `src/main/java` to `target/classes` |
| `mvn test` | Compile and run unit tests |
| `mvn package` | Compile, test and build the JAR or WAR |
| `mvn clean package` | Fresh build from scratch. The everyday command |
| `mvn verify` | Package plus integration checks. Good default for CI |
| `mvn install` | Also copy the artifact into `~/.m2/repository` |
| `mvn deploy` | Also upload it to a remote repository (needs `distributionManagement`) |
| `mvn dependency:tree` | Show direct and transitive dependencies |
| `mvn help:effective-pom` | Show the merged POM Maven really uses |
| `mvn test -Dtest=CalcTest` | Run one test class |
| `mvn package -DskipTests` | Build without running tests (use with care) |
| `mvn -o package` | Offline build from the local repository |
| `./mvnw ...` / `mvnw.cmd ...` | Same commands through the project's Maven Wrapper |

## Mistakes worth remembering

| Mistake | Symptom | Fix |
| --- | --- | --- |
| Running Maven outside the project folder | "there is no POM in this directory" | `cd` into the folder with `pom.xml` |
| `JAVA_HOME` points to `bin` or a JRE | "JAVA_HOME is not defined correctly" or "No compiler is provided" | Point it to the JDK root |
| No Java version in an old POM | "Source option 5 is no longer supported" | Set `maven.compiler.release` |
| `{name}` instead of `${name}` | Literal `{...}` in errors | Always use `${...}` |
| Dependency pasted outside `<dependencies>` | Imports do not compile | Move it inside, reload the IDE |
| Test class not named `*Test` | `Tests run: 0` | Follow Surefire's naming patterns |
| Fixed version on a library the parent manages | Version conflicts at runtime | Remove the version, let the parent manage it |

## Where Maven shows up next in the bootcamp

- **Docker:** a Dockerfile builds the project with Maven and copies the JAR or WAR into an image. See [Single Stage Dockerfile with Maven Spring Boot](/docs/docker/dockerizing-applications/single-stage-dockerfile-with-maven-spring-boot) and [Dockerizing A Maven Web Application](/docs/docker/dockerizing-applications/dockerizing-a-maven-web-application).
- **Jenkins:** every pipeline in the [Jenkins](/docs/jenkins/getting-started) course runs a Maven build and test stage before building the Docker image.
- **AWS:** the Elastic Beanstalk and ECS projects in the [AWS](/docs/aws/getting-started) course deploy JARs that Maven produced.

When one of those builds fails, the skills from this course (reading Maven output, checking `mvn -v`, looking at the dependency tree and the effective POM) are how you find the cause quickly.

## Try It Yourself

1. Without looking at the lessons, create a quickstart project, add spring-core, write one JUnit 5 test, and run `mvn clean verify`.
2. Install that project with `mvn install` and use it as a dependency in a second project.
3. Add the Maven Wrapper to your project with `mvn wrapper:wrapper`, then build with `./mvnw clean package` (or `mvnw.cmd`).
4. Explain to someone else, in under two minutes, what happens when you type `mvn package`.
