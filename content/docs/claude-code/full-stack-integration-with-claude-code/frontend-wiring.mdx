## The prompt: change one function, nothing else

```text title="Prompt: frontend wiring"
In frontend/app.js, the mockFetch() function currently rejects every
request. Replace the BODY of mockFetch() with a real fetch() call to
http://localhost:8000.

Strict rules:
  - Do NOT change the api.* layer that wraps mockFetch.
  - Do NOT touch any other code in app.js.
  - The function signature, return shape, and call sites stay identical.

Only the inside of mockFetch changes, from a rejecting stub to a
real network call that matches the contract in specs/api-contract.md.
```

<Callout type="info" title="Overriding a CLAUDE.md rule on purpose">
Our `CLAUDE.md` says "NEVER modify files in /frontend". This prompt explicitly asks for one change in `app.js` and fences it with strict rules. When you deliberately break a standing rule, say so clearly and keep the scope as small as possible.
</Callout>

### The change

```diff title="frontend/app.js"
 function mockFetch(url, options = {}) {
-  return new Promise((_, reject) => {
-    // Simulate network timeout before refusing
-    setTimeout(() => {
-      reject(new Error(
-        `Cannot connect to backend (${(options.method || 'GET').toUpperCase()} ${url}). ` +
-        'Is the FastAPI server running on localhost:8000?'
-      ));
-    }, 400 + Math.random() * 150);
+  return fetch(`http://localhost:8000${url}`, options).then(async (response) => {
+    let data = null;
+    const contentType = response.headers.get('content-type') || '';
+    if (contentType.includes('application/json')) {
+      data = await response.json();
+    }
+    return { ok: response.ok, status: response.status, data };
   });
 }
```

Remember what the API contract found: the `api.*` methods expect an **envelope** of `{ ok, status, data }`, not a raw `Response`. The new function wraps the real `fetch` result into exactly that shape, so nothing else in the file needs to change. It also handles `DELETE`, which returns `204 No Content` with no JSON body.

The function is still called `mockFetch`, even though it is no longer a mock. That is the cost of "change nothing else". Renaming it is a good small follow-up task.

## Run both servers

```text
Run the frontend and the backend.
```

Watch what Claude does before starting anything. It behaves like a careful developer:

1. Checks the database is migrated (`alembic upgrade head`)
2. Re-runs the seed script, which skips all five existing records thanks to idempotency
3. Starts the backend with uvicorn on port 8000 and checks `/health`
4. Serves the frontend on a separate port

Open the frontend URL in your browser. The board shows the five tasks **from the database**.

<Callout type="warn" title="Ports and CORS">
The backend only accepts browser requests from origins listed in its CORS settings. If the frontend runs on a port that is not in that list (for example 8080 when only 8000 and 5500 were allowed), every request fails with a CORS error in the browser console. The fix is to add that origin to `allow_origins` in `backend/app/main.py`. This exact fix appears later in the project's history.
</Callout>

## Debugging: the board does not update

Click **Move Forward** on a card. Nothing seems to happen. Create a new task. It does not appear.

Is the backend broken? Check before guessing. Refresh `GET /api/tasks` in Swagger: the new task **is** there, and the moved card **has** the new state. So the backend works. The bug is in the frontend: it does not re-render after the API call.

Describe the problem precisely to Claude. A good bug report is half the fix:

```text
When I move a card, the state changes in the backend but the board does not update.
The card stays in the old column. When I create a new task, it is saved in the database
but does not appear on the board. Delete also fails with an error.
```

Claude investigates, reproduces the issue, and finds the cause: `renderBoard()` was drawing from the old in-memory `tasks` array instead of fetching fresh data. The fix is to make `renderBoard()` async and reload the tasks before drawing:

```diff title="frontend/app.js"
-function renderBoard() {
+async function renderBoard() {
+  tasks = await api.getTasks();
+
   const board = document.getElementById('board');
   board.innerHTML = '';
```

It also fixed a related bug in the drag-and-drop handler. Now moves, creates and deletes show up immediately.
