You have a function that works. Now you want it to do a little more: check its values first, or print a line every time it is called. The obvious way is to open the function and add the lines.

That is fine for one function. With two functions you copy the same lines twice. With ten functions you copy them ten times, and every later change has to be made in ten places.

A **decorator** solves this. It is a function that takes another function and gives back a new version of it with extra behaviour around it. The original function is not edited. The lesson builds one step by step, and it uses the idea from [Inner Functions](/docs/python-one-shot/functional-python/inner-functions): a function defined inside another function, and returned from it.

## Step 1: A function, and a twist

Create a new file named `deco.py` with one small function:

```python title="deco.py"
def divide(a,b):
    return a/b


result = divide(4,2)
print(result)
```

```text
2.0
```

Run it with `python deco.py`. Nothing special so far. If the call is changed to `divide(2,4)`, the output is `0.5`, because 2 is divided by 4.

Now the twist. The instructor wants the bigger number to be divided by the smaller number, whatever order the caller uses. The logic is short. If the first value is less than the second, swap them. The swap in one line comes from [Swapping Variables](/docs/python-one-shot/functions-modules-and-input/swapping-variables).

```python title="deco.py"
def divide(a,b):
    if a<b:
        a,b = b,a
    return a/b


result = divide(2,4)
print(result)
```

```text
2.0
```

Problem solved, and no decorator was needed. The need appears with the second function.

## Step 2: The same lines in two functions

Add a function `sub` for subtraction and call both. Without the swap, `sub(2,4)` prints `-2`. To get the bigger number first there too, the lesson copies the two lines from `divide` and pastes them into `sub`:

```python title="deco.py"
def sub(a,b):
    if a<b:
        a,b = b,a
    return a-b

def divide(a,b):
    if a<b:
        a,b = b,a
    return a/b


result1 = divide(2,4)
print(result1)

result2 = sub(2,4)
print(result2)
```

```text
2.0
2
```

It works, and the same two lines now live in two places. The goal of the lesson is to take this common part out, keep it in one place, and then tell each function "use that feature".

## Step 3: A first attempt, and two errors

The lesson removes the swap from both functions and writes an empty function named `greater_first`. The word `pass` means "do nothing here". To use the function as a decorator, write its name with an `@` sign on the line above the function it should change.

{/* check: error */}
```python title="deco.py"
def greater_first():
    pass

@greater_first
def sub(a,b):
    return a-b

@greater_first
def divide(a,b):
    return a/b


result1 = divide(2,4)
print(result1)

result2 = sub(2,4)
print(result2)
```

{/* check: skip */}
```text
Traceback (most recent call last):
  File "C:\PythonCourse\FirstProject\deco.py", line 4, in <module>
    @greater_first
     ^^^^^^^^^^^^^
TypeError: greater_first() takes 0 positional arguments but 1 was given
```

Nobody called `greater_first` with an argument, and still Python says one was given. The `@` line did it. When Python reads `@greater_first` above `def sub`, it calls `greater_first` and passes the function `sub` to it. So a decorator must accept one parameter, the function:

```python
def greater_first(func):
    pass
```

Run again, and a different error appears:

{/* check: skip */}
```text
Traceback (most recent call last):
  File "C:\PythonCourse\FirstProject\deco.py", line 13, in <module>
    result1 = divide(2,4)
TypeError: 'NoneType' object is not callable
```

A function that has no `return` gives back `None`. Python stores whatever the decorator returns under the name `divide`. So `divide` is now `None`, and `None` cannot be called. A decorator must return something that can be called, which means a function.

The quickest way to make the error go away is to return the function that came in:

```python
def greater_first(func):

    return func
```

With this version the file runs and prints `0.5` and `-2`. The decorator takes the function and hands the same function back, so nothing has changed. The empty line in the middle is where the real logic has to go.

<Callout type="info" title="Line numbers in the tracebacks">
In the video, `deco.py` starts with an empty line, so the tracebacks there say line 5 and line 14. The files on this page start on line 1, which gives line 4 and line 13. The error messages are the same.
</Callout>

## Step 4: Wrap the function

To change how the function behaves, the decorator defines an inner function. Any name works. The usual name is `wrap` or `wrapper`, because it wraps the original function. It takes the same parameters as the functions it will stand in for, here `a` and `b`.

```python title="deco.py"
def greater_first(func):
    def wrap(a,b):
        if a<b:
            a,b = b,a
        return func(a,b)
    return wrap

@greater_first
def sub(a,b):
    return a-b

@greater_first
def divide(a,b):
    return a/b


result1 = divide(2,4)
print(result1)

result2 = sub(2,4)
print(result2)
```

```text
2.0
2
```

Two `return` lines do two different jobs:

| Line | What it does |
| --- | --- |
| `return func(a,b)` | Inside `wrap`. Calls the original function with the values, swapped if needed, and passes its result back |
| `return wrap` | Inside `greater_first`. Hands back the function `wrap` itself, without calling it. There are no brackets |

If the caller passes `4,2`, the values go through unchanged. If the caller passes `2,4`, the original function receives `4,2`.

![Decorator_Wraps_A_Function](https://dyz1pdcuffwr5.cloudfront.net/PythonOneShot/py1s-decorator.svg)

<Callout type="info" title="Does a decorator return the same function?">
The instructor says that a decorator takes a function and returns the same function with some modification. To be exact, `greater_first` returns a new function, `wrap`. The original `sub` is not modified. It is kept inside `wrap` under the name `func` and called from there.
</Callout>

## Step 5: What the @ sign does

To show how this works, the lesson removes the two `@` lines and writes the same thing by hand:

```python title="deco.py"
def greater_first(func):
    def wrap(a,b):
        if a<b:
            a,b = b,a
        return func(a,b)
    return wrap

def sub(a,b):
    return a-b

def divide(a,b):
    return a/b

sub = greater_first(sub)
divide = greater_first(divide)

result1 = divide(2,4)
print(result1)

result2 = sub(2,4)
print(result2)
```

```text
2.0
2
```

Read `sub = greater_first(sub)` from right to left:

1. The function `sub` is passed to `greater_first`, where it is known as `func`.
2. `greater_first` returns `wrap`.
3. The name `sub` now refers to `wrap`.

So where is `wrap` called? In the line `sub(2,4)`. That call runs `wrap(2,4)`, which swaps the values and then calls the original function.

Writing `@greater_first` above a function does exactly this assignment for you. Both forms work. The `@` form is the one used today, and you will see it a lot once you work with Python frameworks. The lesson puts the `@` lines back and turns the two manual lines into comments.

## Step 6: A second decorator for logging

A decorator is not limited to swapping numbers. Any logic that should run around a function can go into one. The lesson writes a second decorator that keeps a **log**, a record of what happened: which values came in and what the result was.

```python title="deco.py"
def log_deco(func):
    def wrap(a,b):
        print("values ", a, " ", b)
        result = func(a,b)
        print("Result ", result)
        return result
    return wrap

def greater_first(func):
    def wrap(a,b):
        if a<b:
            a,b = b,a
        return func(a,b)
    return wrap

@log_deco
@greater_first
def sub(a,b):
    return a-b

@log_deco
@greater_first
def divide(a,b):
    return a/b

# sub = greater_first(sub)
# divide = greater_first(divide)

result1 = divide(8,20)
print(result1)

result2 = sub(2,4)
print(result2)
```

```text
values  8   20
Result  2.5
2.5
values  2   4
Result  2
2
```

Points to notice:

- The wrapper stores the result in a variable, prints it, and returns the same variable. That way the original function is called only once.
- Writing `log_deco` is not enough. Nothing is logged until `@log_deco` is placed above a function. In the lesson it is first added to `sub` only, and only `sub` is logged.
- The call is changed to `divide(8,20)` so that you can tell the two logs apart.
- A function can carry more than one decorator. This is called stacking.
- A real program usually writes its log to a file and not to the screen.

<Callout type="info" title="Why the log shows 8 and 20, and still 2.5">
This detail is an addition to the lesson. Stacked decorators are applied from the bottom up, so the two lines mean `divide = log_deco(greater_first(divide))`. The logging wrapper is on the outside. It sees the values as the caller wrote them, 8 and 20. Then the inner wrapper swaps them, and the result is 20 divided by 8, which is 2.5.
</Callout>

## Step 7: A wrapper that accepts any number of arguments

Next comes a third function, `add`. It does not need `greater_first`, because the order does not matter for addition. It should still be logged, so it gets `@log_deco` only. With two numbers, `add(5,7)`, the log shows `values  5   7` and `Result  12`.

Then the lesson gives `add` a third parameter and calls `add(5,7,6)`. The instructor expects a problem, and here it is:

{/* check: error */}
```python title="deco.py"
def log_deco(func):
    def wrap(a,b):
        print("values ", a, " ", b)
        result = func(a,b)
        print("Result ", result)
        return result
    return wrap

@log_deco
def add(a,b,c):
    return a+b+c

result3 = add(5,7,6)
print(result3)
```

{/* check: skip */}
```text
Traceback (most recent call last):
  File "C:\PythonCourse\FirstProject\deco.py", line 13, in <module>
    result3 = add(5,7,6)
TypeError: log_deco.<locals>.wrap() takes 2 positional arguments but 3 were given
```

The listing above shows only the part of the file that matters for the error. In the video the other two functions are still in the file, their output is printed first, and the traceback says line 40.

Read the last line. The function that complains is `wrap`, not `add`. The name `add` now refers to `wrap`, and `wrap(a,b)` takes exactly two values.

Writing one decorator for two values, another for three and another for five is no solution. The lesson goes back to the idea from [Function Arguments](/docs/python-one-shot/arrays-and-recursion/function-arguments): a parameter written as `*args` collects any number of values into a tuple. In the call `func(*args)`, the star does the opposite and spreads the tuple out into separate values again.

```python title="deco.py"
def log_deco(func):
    def wrap(*args):
        print("values ", args)
        result = func(*args)
        print("Result ", result)
        return result
    return wrap

def greater_first(func):
    def wrap(a,b):
        if a<b:
            a,b = b,a
        return func(a,b)
    return wrap

@log_deco
@greater_first
def sub(a,b):
    return a-b

@log_deco
@greater_first
def divide(a,b):
    return a/b

@log_deco
def add(a,b,c):
    return a+b+c

# sub = greater_first(sub)
# divide = greater_first(divide)

result1 = divide(8,20)
print(result1)

result2 = sub(2,4)
print(result2)

result3 = add(5,7,6)
print(result3)
```

```text
values  (8, 20)
Result  2.5
2.5
values  (2, 4)
Result  2
2
values  (5, 7, 6)
Result  18
18
```

The values are now printed as tuples, and the same decorator works for functions with two and with three parameters. This is how a decorator is normally written.

`greater_first` still uses `a,b`. The instructor leaves it that way, because its logic would have to change, and suggests it as practice for you.

## Step 8: Keyword arguments too

One case is still open. A caller can also pass a value with its name, for example `add(5,7,c=6)`. A wrapper with only `*args` does not accept that. For the safer side, the lesson adds a second parameter, `**kwargs`, which collects all keyword arguments:

```python
    def wrap(*args, **kwargs):
```

<Callout type="warn" title="The video stops one edit early">
In the video only the `def wrap` line is changed. The call inside the wrapper still reads `func(*args)`. The instructor then clears the terminal and runs `python deco.py` once more. The same nine output lines appear, and he says it is still working. The unfinished call does not show as a problem there, because the program only passes positional arguments. With a keyword argument, as in `add(5,7,c=6)`, that state fails. The value `c=6` is accepted by `wrap` and then dropped, so the original function never receives it, and the run ends with `TypeError: add() missing 1 required positional argument: 'c'`. The finished form passes both on: `func(*args, **kwargs)`.
</Callout>

This is the finished `log_deco`. The rest of the file stays as in Step 7, and the output is the same as there.

```python title="deco.py"
def log_deco(func):
    def wrap(*args, **kwargs):
        print("values ", args)
        result = func(*args, **kwargs)
        print("Result ", result)
        return result
    return wrap

@log_deco
def add(a,b,c):
    return a+b+c

result3 = add(5,7,6)
print(result3)
```

```text
values  (5, 7, 6)
Result  18
18
```

With this version the call `add(5,7,c=6)` also works and gives 18. The log line then shows `values  (5, 7)`, because only `args` is printed.

## The shape of a decorator

| Part | Purpose |
| --- | --- |
| `def log_deco(func):` | The decorator. It receives the function to change |
| `def wrap(*args, **kwargs):` | The inner function that will be called in place of the original |
| Lines before `func(...)` | Extra work before the original runs, such as a check or a log line |
| `result = func(*args, **kwargs)` | The call to the original function |
| `return result` | Gives the original result back to the caller |
| `return wrap` | Hands the wrapper back, without brackets |
| `@log_deco` | Placed above a function to apply the decorator |

## Additions beyond the lesson

**`functools.wraps`.** After decoration, the name `add` refers to the wrapper, so `add.__name__` gives `'wrap'` and not `'add'`. Python has a helper that copies the name and the description of the original function onto the wrapper. Write `from functools import wraps` at the top and put `@wraps(func)` on the line above `def wrap`. Then `add.__name__` gives `'add'` again. Most real decorators use it.

## Mistakes and fixes

| What you see | Cause | Fix |
| --- | --- | --- |
| `TypeError: greater_first() takes 0 positional arguments but 1 was given` | The decorator has no parameter, and `@` passes the function to it. This happens in the lesson | Write `def greater_first(func):` |
| `TypeError: 'NoneType' object is not callable` | The decorator returns nothing, so the decorated name becomes `None`. This happens in the lesson | Return a function from the decorator |
| The decorator is applied and the output does not change | The decorator returns `func` itself. This happens in the lesson | Define an inner function with the new logic and return that |
| A red line under `print("values ", a, " " b)` | A comma is missing before `b`. This happens in the lesson, and the editor shows it before the file is run | Write `print("values ", a, " ", b)` |
| No log lines are printed | The decorator was written and never placed above a function. This happens in the lesson | Add `@log_deco` above the function |
| `TypeError: log_deco.<locals>.wrap() takes 2 positional arguments but 3 were given` | The wrapper has a fixed number of parameters. This happens in the lesson | Use `def wrap(*args, **kwargs):` and `func(*args, **kwargs)` |
| `TypeError: add() missing 1 required positional argument: 'c'` | The wrapper accepts `**kwargs` and calls `func(*args)`, so `c=6` is lost | Pass both on with `func(*args, **kwargs)` |
| `TypeError: greater_first.<locals>.wrap() missing 2 required positional arguments: 'a' and 'b'` | `return wrap()` was written with brackets, so the wrapper is called at once, with no values | Write `return wrap` |
| `TypeError: log_deco.<locals>.wrap() got an unexpected keyword argument 'c'` | The wrapper has only `*args` and the call uses `c=6` | Add `**kwargs` to the wrapper and to the call of `func` |
