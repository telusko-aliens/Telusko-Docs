In [List Functions](/docs/python-tutorial-2026/data-structures-and-types/list-functions) you added values to a list and removed them again. At the end the list was `[23, 55, 44, 56, 11, 99]`.

A list of numbers raises more questions than "what is in it". Which value is the smallest? Which is the largest? What is the total? And what if two values are wrong and have to be swapped for new ones? This lesson answers all of these, first with the list itself and then with three functions that are built into Python.

## Step 1: Replace several values

The lesson prints the list once more and then replaces two of its values in one line:

```python
>>> nums = [23, 55, 44, 56, 11, 99]
>>> nums[2:4] = [54,76]
>>> nums
[23, 55, 54, 76, 11, 99]
```

The second line assigns to a slice. `nums[2:4]` stands for the values at index 2 and 3, which are 44 and 56, and the assignment replaces them with 54 and 76.

This is the exact operation that failed for a string in [Fetching Characters from a String](/docs/python-tutorial-2026/python-basics/fetching-characters-from-a-string), where `text[0:3] = 'TEL'` gave a `TypeError`. It works here because a list is mutable, which means it can be changed, as [List Functions](/docs/python-tutorial-2026/data-structures-and-types/list-functions) explained.

## Step 2: Reverse, sort, min, max and sum

```python
>>> nums = [23, 55, 54, 76, 11, 99]
>>> nums.reverse()
>>> nums
[99, 11, 76, 54, 55, 23]
>>> nums.sort()
>>> nums
[11, 23, 54, 55, 76, 99]
>>> min(nums)
11
>>> max(nums)
99
>>> sum(nums)
318
```

`reverse()` turns the order around. `sort()` puts the values in order, smallest first. Both change the list itself and print nothing.

`min`, `max` and `sum` are different. They are built-in functions of Python, not methods of the list. You pass the list to them in round brackets, and they return the smallest value, the largest value and the total.

`min` also works on a list of strings:

```python
>>> names = ['navin','harsh','kiran']
>>> min(names)
'harsh'
```

Strings are compared in alphabetical order. `h` comes before `k` and `n`, so `'harsh'` is the minimum. By the same rule `max(names)` gives `'navin'`, as the instructor says without running it.

A total of names makes no sense, and Python agrees:

## List operations in this lesson

| Code | What it does | Changes the list |
| --- | --- | --- |
| `nums[2:4] = [54,76]` | Replaces a slice | Yes |
| `nums.reverse()`, `nums.sort()` | Reverses or sorts | Yes |
| `min(nums)`, `max(nums)`, `sum(nums)` | Smallest, largest, total | No |

## Mistakes and fixes

| What you see | Cause | Fix |
| --- | --- | --- |
| `TypeError: unsupported operand type(s) for +: 'int' and 'str'` | `sum` was used on a list of strings. This is shown in the lesson | Use `sum` on lists of numbers only |
| Nothing is printed after `nums.reverse()` or `nums.sort()` | These methods change the list and return nothing to show | Type `nums` to see the list |
| `TypeError: '<' not supported between instances of 'int' and 'str'` | `sort` was called on a list that holds numbers and strings, such as `['navin',67,6.5]`. Python cannot say which of the two comes first | Sort lists that hold numbers only, or strings only |
